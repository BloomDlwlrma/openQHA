# Collect leaves one Table: `collect.dat`, sections named, columns explained

Status: ready-for-agent
Date: 2026-09-16
Vocabulary: CONTEXT.md (Record, Report, Property file, **Table**, Calculation).
Decisions: docs/adr/0003 (amendment 2026-09-16).
Grilling: `.mem/notes/notes_2026-09-16_verifiability-grill-round-1.md` (Q2),
`.mem/notes/notes_2026-09-16_collect-one-dat-grill-round-2.md` (Q1-Q9).

## Problem Statement

Collect leaves four `.dat` files beside its Report, each a bare header line over
abbreviated column names (`TS_QH_rms_about_mean_kcal`, `rigid_ratio`,
`S_vib_kcal_per_K`, `terms_match_hessian_route`) that nothing on disk explains. A reader
opening the molecule directory has to know which of the four holds what, and then open
the analysis code to learn what a column means. The criteria are written three times
(the `.criteria.dat`, the `Criteria` section of `collect.out`, and again inside the
expanded dump at the end of `collect.out` as an unreadable 400-column table), and the
ensemble reads its pass count from the `.dat` where the Property file already carries it.

## Solution

Collect leaves ONE Table, `collect.dat`, with three named sections (`trajectories`,
`blank`, `assembly`) and, above each section's header, one comment line per column
saying its type, its unit and what it is, in the words the Property file uses. The
criteria are printed once, in the `Criteria` section of `collect.out`, and their counts
live in `collect.toml` where the ensemble reads them. The expanded dump at the end of
`collect.out` no longer repeats the rows the Table and the `Criteria` section hold.

    <molecule>/_records/md_<route>/
      collect.out          the Report (Criteria section unchanged; dump without the table rows)
      collect.toml         [Calculation_Status] [Calculation_Info] [Criteria]   (unchanged)
      collect.dat          the Table: [trajectories] [blank] [assembly]
      collect_s2.dat       the same for setting s2 (the stem rule)

    [trajectories]
    #   species           String: the molecule (QM9 index)
    #   basin             String: the basin folder the trajectory started from (basin00, ...)
    #   seed              String: the seed folder label (seed00; one seed per basin since 2026-09-13)
    #   n_frames          Integer: frames the covariance was formed from
    #   TS_QH_kcal        Double, kcal/mol: T*S from the quasi-harmonic entropy of this trajectory
    ...
    # species basin seed n_frames TS_QH_kcal ...
    dsgdb9nsd_000035 basin00 seed00 5 1.6432667279114774 ...

    [blank]
    ...

## User Stories

1. As the user, I want collect to leave one `.dat`, so that a molecule's tables are one file beside `collect.out` and `collect.toml`, not four.
2. As the user, I want each table inside it introduced by a `[section]` line, so that I can tell the trajectories from the blank control from the assembly without knowing a file-name convention.
3. As the user, I want every column explained in a comment above the header (type, unit, meaning), so that `TS_QH_rms_about_mean_kcal` needs no trip to the code.
4. As the user, I want the column comments in the same `Type, unit: doc` form as the Property file's, so that the two files beside each other read as one convention.
5. As the user, I want the column names left as they are, so that a row stays readable when its header scrolls off and nothing that keys on them changes.
6. As the user, I want all three sections written every time, header and comments included even with no rows, so that "no rows" and "no section" are different things.
7. As the user, I want the criteria printed once, in the `Criteria` section of `collect.out`, so that a verdict with its measure is found in one place.
8. As the user, I want the ensemble to read collect's pass count from `collect.toml`, so that the Property file is what a later step reads back, as the glossary says.
9. As the user, I want the expanded dump at the end of `collect.out` to stop repeating the trajectories, blank, assembly and criteria rows, so that the dump holds only what nothing else holds.
10. As the user, I want the per-trajectory analysis (saturation curve, mode batches, spectrum) kept in that dump, so that no number leaves `collect.out`.
11. As the user, I want a setting's Table named by the stem rule (`collect_s2.dat`), so that it sits beside `collect_s2.out` and `collect_s2.toml` as engine files do.
12. As the user, I want an undocumented column to fail a test, so that a column added later cannot appear without its explanation.
13. As the user, I want a Table reader that returns the sections by name, so that the ensemble asks for `trajectories` and never parses a file layout.
14. As the user, I want a single-section `.dat` (no `[section]` line) still to read back, so that a table written by hand or by an older tool is not refused.
15. As the user, I want the shipped propanal sample records regenerated by running collect and the ensemble again, so that the sample is what the code writes.
16. As the user, I want the docs that list the four files to list the one, so that the tree in the README matches the tree on disk.
17. As the user, I want a glossary term for the Table, so that the word is fixed and "the four tables" is not used again.
18. As the user, I want each step to tell me what to commit, so that I track the work on GitHub myself.

## Implementation Decisions

- **One Table, three sections.** The collect Calculation writes `collect.dat` (stem rule
  for a setting) holding, in this order, `trajectories`, `blank`, `assembly`; always all
  three. The criteria are not a section: they stay in the `Criteria` section of the
  Report and the `[Criteria]` block of the Property file, both unchanged.
- **Section syntax.** A bare `[name]` line opens a section (TOML/INI style, the Property
  file's look). It is followed by the column comment lines, the `# col col ...` header
  line, the rows, and a blank line. A `#` line inside a section that is not the header is
  a comment; the header is the first `#` line whose tokens are exactly the column names,
  which the writer guarantees by putting the comments first and the header last.
- **Column comments from a schema.** The collect record module holds a column schema of
  the Property-file shape, `{section: {column: (Type, unit or None, doc)}}`, and the
  Table writer takes it. The writer emits one comment per column in the order of the
  header; a column in the rows that the schema does not know is written without a
  comment and returned by the writer (the `prop.write` rule), and collect's test asserts
  the returned list is empty. Column names are unchanged.
- **The column meanings**, as the schema will carry them (the decision-rich content; the
  wording is settled here so the ticket writes it, not invents it):

  `trajectories` (one row per trajectory):
  species — String: the molecule (QM9 index). basin — String: the basin folder the
  trajectory started from. seed — String: the seed folder label (one seed per basin since
  2026-09-13). n_frames — Integer: frames the covariance was formed from. TS_QH_kcal —
  Double, kcal/mol: T*S from the quasi-harmonic entropy (mode by mode from the
  mass-weighted covariance). TS_Schlitter_kcal — Double, kcal/mol: T*S from Schlitter's
  upper bound on the same covariance. S_QH_kcal_per_K — Double, kcal/(mol K): the
  quasi-harmonic entropy itself. A_vib_kcal — Double, kcal/mol: vibrational Helmholtz
  energy summed over the quasi-harmonic modes. lowest_frequency_cm_inv /
  highest_frequency_cm_inv — Double, cm^-1: softest and stiffest quasi-harmonic mode.
  n_nonzero — Integer: covariance eigenvalues above the rank tolerance (criterion 9).
  expected_modes — Integer: 3N-6, the modes a full-rank covariance has. rigid_ratio —
  Double: first vibrational eigenvalue over the largest rigid-body one on the unprojected
  covariance; inf when the rigid ones vanish (criterion 4's separation).
  saturation_last_doubling_kcal — Double, kcal/mol: rise of T*S_QH over the last
  doubling of trajectory length (criterion 1's increment). wall_seconds — Double, s:
  production wall time of the run that finished the trajectory. seconds_per_ps —
  Double, s/ps: that run's cost per picosecond of its own frames.

  `blank` (one row per basin): species, basin as above. n_seeds — Integer: trajectories
  of this basin. TS_QH_mean_kcal — Double, kcal/mol: mean T*S_QH over the seeds.
  TS_QH_spread_kcal — Double, kcal/mol: max minus min over the seeds.
  TS_QH_rms_about_mean_kcal — Double, kcal/mol: root-mean-square of T*S_QH about its
  mean over the seeds, the noise floor of criterion 5. standard_error_kcal — Double,
  kcal/mol: sample standard deviation over sqrt(n_seeds); NA with one seed. note —
  String: why the floor is not measured, when it is not.

  `assembly` (one row per basin): species, basin as above. G_minus_Eel_kcal — Double,
  kcal/mol: G minus E_el assembled from the quasi-harmonic spectrum with the same
  translational, rotational and electronic terms as the Hessian route. A_vib_kcal —
  Double, kcal/mol: the vibrational term of that assembly. S_vib_kcal_per_K — Double,
  kcal/(mol K): the vibrational entropy of that assembly. terms_match_hessian_route —
  Boolean: the translational, rotational and electronic terms are identical to the
  Hessian route's (criterion 7).
- **Table reader.** The table module gains a reader that returns `{section: rows}`; a
  file with no `[section]` line reads back as one unnamed section, so the existing
  single-table reader keeps working on it. The single-table reader on a sectioned file
  refuses, naming the sections, rather than silently returning the first.
- **Ensemble reads the Property file for the verdict.** The ensemble's pass count and
  total come from `[Criteria] N_PASSED / N_TOTAL` in `collect.toml`; its T*S rows come
  from the `trajectories` section of `collect.dat`. Absence of the Table is refused as
  the absence of the trajectories table is today.
- **Report dump trimmed.** The expanded dump at the end of `collect.out` drops the
  `trajectories`, `blank_control`, `assembly` and `criteria` row lists; the per-trajectory
  analysis, saturation and mode-batch dicts, the declaration and the GROMACS cross-check
  stay. The `Criteria` section is unchanged.
- **Write order unchanged.** Table, then Report, then Property file last (its STATUS is
  the marker).
- **Paths.** The collect record module's path helper returns the `out`, `toml` and one
  `dat` for a stem; the four table keys go. The layout module is untouched (the stem
  rule already covers `collect_s2.dat`).
- **Docs.** The output inventory (section 8), the records inventory, the branch B
  production page, the repository README and the propanal example README name
  `collect.dat`; the collect Property file's `N_TOTAL` comment points at `collect.out`
  only. CONTEXT.md and ADR 0003 are already updated (this session).
- **Sample records.** Collect and the ensemble are re-run on the propanal engine files
  already on disk for both routes; the eight old `.dat` are deleted, the two `collect.dat`
  and the refreshed `collect.out`, `collect.toml`, `ensemble.out`, `ensemble.toml` are
  committed.

## Testing Decisions

A good test reads the file back and checks what a reader gets, never how the writer
built it. Prior art: `tests/unit/t_dat_table_roundtrip.py` (write then read, one defect
story each), `tests/unit/t_report_reads_collect.py` (a fake collect product under a
temporary root, the ensemble reads it), `tests/integration/t_ase_engine_folder.py`
(the whole ASE chain on propanal, the Record checked on disk). Seams, highest first:

1. **Integration (existing seam):** the ASE engine-folder chain ends with exactly
   `collect.out`, `collect.toml`, `collect.dat` in `_records/md_ase/` (no other `.dat`),
   `collect.dat` has the three sections in order with a comment for every header column,
   and the ensemble runs on it.
2. **Unit, table module:** a sectioned file round-trips `{section: rows}` with the same
   value fidelity as today; a file without sections reads as before; the single-table
   reader refuses a sectioned file by naming its sections; an empty section reads as `[]`.
3. **Unit, collect record:** the column schema documents every column collect writes
   (the writer returns no unknown columns); the comments carry the type, the unit and the
   doc in the Property-file form.
4. **Unit, ensemble reads collect (existing, extended):** the fake product is one
   `collect.dat` plus `collect.toml`; the ensemble's T*S per basin comes from the
   `trajectories` section and its verdict from `[Criteria]`; a product with no
   `collect.dat` is refused by name.
5. **Report dump:** `collect.out` contains each criterion sentence exactly once.

## Out of Scope

- The criteria's form in the Report (unchanged) and in the Property file (unchanged).
- Renaming any column, or changing what collect computes.
- The 02d, branch A, MD and ensemble Records: none writes a Table.
- The `.out` renderer's wide-table layout for lists of dicts (the offending dump rows are
  removed, the renderer is not redesigned).
- The stale error text "no meta.json in ..." in collect (noted 2026-09-16, a separate
  one-line fix).

## Further Notes

- `[section]` lines are a TOML look, not TOML: the file stays a whitespace table and the
  standard library still needs no parser beyond `shlex`.
- The propanal sample's `md_openmm/basinNN/system.xml` (36 MB each) stays out of the
  repository; the re-run touches `_records/` only.
